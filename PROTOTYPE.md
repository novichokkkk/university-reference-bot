# Лабораторная работа 6 — прототип

Реализованы пять демонстрационных разделов базы знаний, классификатор по ключевым словам,
ответ из PostgreSQL, неизвестный/неоднозначный запрос, локальный web-стенд и Telegram long polling.
Это частичная реализация задач 1.1–4.3 из ЛР2–3, а не завершение этапа Э3.
В базе пять записей вместо запланированных двадцати. Все ответы явно демонстрационные.

## Запуск в IntelliJ IDEA

1. Открыть pom.xml как Maven-проект, выбрать JDK 21.
2. В PostgreSQL создать отдельную пустую базу `university_reference_bot`.
3. В Run Configuration задать `SPRING_PROFILES_ACTIVE=prototype`, `DB_USERNAME`, `DB_PASSWORD`.
   При другом адресе базы задать `DB_URL=jdbc:postgresql://localhost:5432/university_reference_bot`.
4. Запустить UniversityReferenceBotApplication.
5. Открыть http://localhost:8080/prototype.html.

Flyway создаёт только prototype_knowledge и таблицу истории миграций; Hibernate проверяет схему.
Не запускать этот учебный профиль на производственной базе. Web-стенд доступен только с локального компьютера.

## Telegram

В той же Run Configuration добавить `TELEGRAM_ENABLED=true` и `TELEGRAM_BOT_TOKEN`
со своим действующим токеном из BotFather. Не добавлять токен в файлы, Git или скриншоты.
После перезапуска открыть личный чат с ботом и отправить /start, «Как поступить?»,
«Расписание», «Погода», «Контакты и расписание». Только один экземпляр должен получать обновления;
для polling у бота не должно быть активного webhook.

Повторы после сетевого сбоя/перезапуска возможны: offset пока хранится в памяти.
Перед релизом нужны постоянное хранение offset, обработка 429/retry_after и тесты сетевых отказов.

## Проверка

`mvn clean verify` — тесты, Checkstyle, JaCoCo и JAR.
30 контрольных фраз в PrototypeTest проверяют ожидаемую метку и негативные сценарии.
Результат на этом небольшом наборе не означает точность 90% на реальных запросах студентов.
Отдельная интеграционная проверка использует H2; PostgreSQL нужно проверять отдельным запуском.

Пример REST-запроса: POST /api/prototype/ask, JSON: {"text":"Как поступить?"}.
Ожидается intent=ADMISSION, demo=true и демонстрационный ответ из БД.
Пустая строка и текст длиннее 1000 символов возвращают HTTP 400.

Не реализованы реальные расписание/контакты, профиль, административный интерфейс и авторизация.
Отчёт хранится отдельно в reports, папка docs проекту не нужна.
